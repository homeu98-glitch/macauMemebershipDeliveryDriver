SiteA to SiteB API Guide

This guide documents the current SiteA integration surface for the driver system, including order creation, status queries, cancel, raise-price, customer hurry-up, and SiteB callbacks.

SiteA = Main customer/shop system SiteB = Driver app + backoffice Auth = JWT bearer token Transport = JSON over HTTPS

Base values

Production SiteB base URL

https://macau-delivery.vercel.app

Shared secret

SITEB_DELIVERY_CLIENT_SECRET / JWT_SHARED_SECRET (same value configured on SiteB)
All examples below use {SITEB_BASE_URL}. Replace it with the real deployed SiteB backoffice domain.

Authentication

SiteA first requests a short-lived JWT from SiteB, then sends it in the Authorization header.

POST /api/v1/auth/token
{
  "clientId": "macau-ledger",
  "clientSecret": "SITEB_DELIVERY_CLIENT_SECRET",
  "audience": "siteb-api"
}
{
  "accessToken": "<jwt>",
  "tokenType": "Bearer",
  "expiresIn": 3600
}

Headers

Authorization: Bearer <accessToken>
Content-Type: application/json

Cancel order

POST /api/v1/orders/{externalOrderId}/cancel
{
  "reason": "shop_owner_cancelled",
  "requestedBy": "sitea-shop-admin",
  "requestedAt": "2026-07-06T10:35:00+08:00"
}

If the order has already been picked up or delivered, SiteB returns 409.

Customer hurry-up

POST /api/v1/orders/{externalOrderId}/hurry
{
  "message": "客人催單啦，請盡快送達。",
  "requestedBy": "sitea-customer-app",
  "requestedAt": "2026-07-06T11:20:00+08:00"
}
{
  "success": true,
  "externalOrderId": "SITEA-ORDER-20260706-001",
  "status": "picked_up",
  "pushed": true
}
This endpoint sends a push notification to the currently assigned driver with the dedicated customer_hurry sound.

SiteB to SiteA callbacks

SiteB sends callbacks to the URL provided in callback.url when driver-side status changes happen.

Driver action Callback eventType Main fields
Driver accepted order.accepted externalOrderId, status, driver.name, driver.phone, driver.distanceToShopKm
Driver picked up order.picked_up externalOrderId, status, driver
Driver arrived order.arrived externalOrderId, status
Driver delivered order.delivered externalOrderId, status, proof.imageUrl, proof.uploadedAt
Driver reported exception order.exception_reported externalOrderId, status, exception.reason, exception.action

Recommended status handling

SiteB order status Meaning on SiteA
newCreated, waiting for driver acceptance
acceptedDriver assigned and heading to shop
picked_upDriver has picked up the order
arrived_customerDriver is at / near customer
deliveredOrder completed
canceledOrder canceled

Integration notes

  • Use externalOrderId as the permanent cross-system key.
  • siteBOrderId is the SiteB internal UUID and is useful for debugging.
  • Proof photos are uploaded to the delivery-proofs bucket and the file path is stored in delivery_proofs.storage_path.
  • Proof viewing URLs are signed and temporary. If SiteA needs a stable internal reference, store the path, not the signed URL.
  • The new customer hurry-up endpoint is for notifying the currently assigned driver. It does not change the order status by itself.
