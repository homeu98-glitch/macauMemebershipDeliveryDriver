SiteA ↔ SiteB 派送 API 規格 v2

這份文檔以目前已實作、可在現行系統上工作的行為為準，包含建單、查單、取消、加價、催單、Webhook callback、安全驗簽與已知限制。

Production Base URL: https://macau-delivery.vercel.app 外部訂單鍵值: externalOrderId Idempotent: POST /api/v1/orders Webhook HMAC: 已支援

環境與可用性

項目 目前狀態
Production https://macau-delivery.vercel.app
Staging / Sandbox 目前未提供獨立 staging/sandbox 環境與獨立測試憑證。
clientId / clientSecret clientId = macau-ledger。clientSecret 由雙方線下保存，Server 目前驗證共享 secret，並支援新舊 secret 並存。
正式網址已更新為 macau-delivery.vercel.app，後續 SiteA 對接請以這個網域為準。

授權

SiteA 先向 SiteB 換取 JWT，再使用 Bearer Token 呼叫其他 v1 API。

POST /api/v1/auth/token
{
  "clientId": "macau-ledger",
  "clientSecret": "SITEB_DELIVERY_CLIENT_SECRET",
  "audience": "siteb-api"
}
{
  "success": true,
  "accessToken": "<jwt>",
  "tokenType": "Bearer",
  "expiresIn": 3600
}
Token 過期或簽章錯誤時，其它 v1 API 會回傳 401。目前 server 支援 JWT_SHARED_SECRET 與 JWT_SHARED_SECRET_PREVIOUS 同時有效，方便做 secret 輪換寬限。

共用 Header

Authorization: Bearer <accessToken>
Content-Type: application/json

Webhook callback

當 SiteB 端訂單狀態改變時，會 POST 到建單時提供的 callback.url。

Header

Content-Type: application/json
Authorization: Bearer <siteb-callback-jwt>
X-SiteB-Timestamp: 2026-07-06T11:20:00.000Z
X-SiteB-Signature: HMAC_SHA256_HEX(timestamp + "." + rawBody)

只有在建單時提供 callback.secret 時，SiteB 才會送出 HMAC Header。

驗簽算法

signature = hex(
  HMAC_SHA256(callback.secret, X-SiteB-Timestamp + "." + rawRequestBody)
)

Ack 規則

  • SiteA 回傳任何 2xx，即視為 callback 成功。
  • 回傳 HTTP 200 搭配 { "ok": true } 當然可以。

重試策略

  • 目前系統沒有自動重試排程。
  • 失敗 callback 會寫入 backoffice callback log，可由後台手動重送。
SiteA 若需要固定 1/5/15 分鐘這種自動重試策略，這屬於下一階段能力，現在的正式文檔不應假設它已存在。

例外 reason / action

欄位 目前會出現的值 說明
exception.reason driver_reported_issue 或車手輸入文字 目前沒有完整固定 enum；若車手輸入自訂內容，會直接帶出。
exception.action pending_review 目前預設為等待人工處理。
若 SiteA 需要完整 enum 契約，建議下一輪將 exception reason/action 固定為受控代碼表。目前版本屬於可用，但不是最終嚴格枚舉版。

重新派單說明

目前沒有提供「原單直接 re-dispatch」的獨立 API。若 SiteA 要重新建立新的派送流程，建議使用新的 externalOrderId 重新建單。

錯誤格式

v1 API 已統一使用以下錯誤格式：

{
  "success": false,
  "error": {
    "code": "order_not_found",
    "message": "Order not found."
  }
}
HTTP code 典型情境
400bad_request / create_order_failed缺參數、時間格式不合法、欄位校驗失敗
401unauthorized / invalid_clientJWT 無效、token 過期、clientSecret 不正確
404order_not_found查無 externalOrderId
409order_conflict訂單已不可取消
500*_failed服務端例外

命名統一

  • 取消狀態統一使用美式拼法 canceled。
  • 抵達客戶狀態統一使用 arrived_customer；callback eventType 為 order.arrived_customer。
  • driver 欄位統一為 driver.fullName + driver.phone。

Rate limit

目前未在 API 層另外宣告固定 QPS 限制；請以合理頻率呼叫。若未來要正式對接高流量情境，建議下一輪補上 tenant 級限流與配額。

Webhook URL 模式

目前系統是每張訂單透過 callback.url 帶入 callback 位置。Tenant-level 固定 Webhook URL 目前尚未提供。

如果 SiteA 要改成租戶級固定 webhook，建議下一輪新增 merchant / tenant 設定表，讓 callback.url 與 callback.secret 從租戶配置中繼承，而不是每單傳入。
